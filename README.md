# 静读 · 私人书房

React + TypeScript + Vite 的私人 TXT 小说阅读器。无账户、无追踪、无正文上传；支持 iPhone Safari、Windows Chrome 和离线 PWA。原始小说不包含在应用内，也不提交至仓库。

本次构建、14 项单元测试和 12 项 Chrome/WebKit 浏览器测试已通过；真实 iPhone 验收尚待进行。详细结果和限制见 [TESTING.md](./TESTING.md)。

## 启动

需要 Node.js 22.12+（或 24 LTS）。

```sh
npm ci
npm run dev
```

本机打开终端输出的 localhost 地址。手机可通过同一局域网的电脑 IP 体验基本功能，但 **HTTP 局域网地址不能测试 PWA**；iPhone 的安装与离线验收请使用 GitHub Pages 的 HTTPS 地址。

```sh
npm test
npm run build
npm run preview
npm run test:e2e
```

端到端测试会启动 4173 端口的严格静态服务器，挂载到 `/jingdu/` 子路径以模拟 Pages。测试覆盖移动尺寸的 Chrome 与 WebKit 引擎。Windows 如安装了标准位置的 Chrome，会直接使用；其他环境先运行 `npx playwright install chromium`，WebKit 测试需先运行 `npx playwright install webkit`。浏览器引擎模拟不等同于真实 iPhone Safari 测试。

## 使用

1. 点击“导入书籍”，选择 TXT；检查编码、正文预览，修改书名与作者后加入书架。
2. 打开书籍。轻点正文可隐藏菜单；右下角的省略号可重新唤出。阅读器提供目录搜索、上一节/下一节、书签及外观设置。
3. 进度按书籍独立保存，滚动时每约 600ms 写入；离开阅读页、切章节和页面隐藏时也会尝试写入。
4. “阅读与数据 → 导出完整备份”下载 `.jingdu.json` 文件，包含所有正文、元数据、进度、书签及设置。iPhone 请确认文件已保存到“文件”应用。
5. “从备份恢复”先校验完整性，再显示替换确认；确认后以一个 IndexedDB 事务替换整个书架，失败会回滚。恢复不是合并。
6. 书籍详情可查看文件信息、阅读进度，并确认删除书籍及其书签。

## iPhone 安装与离线

1. 在 Safari 在线打开部署后的 HTTPS 网站。
2. 分享 → 添加到主屏幕 → 添加（如出现选项，请启用“作为网页 App 打开”）。
3. **先从主屏幕打开，再导入书籍。** Safari 标签页与主屏幕应用可能使用独立存储；迁移时在原入口导出、在目标入口恢复。
4. 首次在线打开并等待加载完成，再断开网络重新打开，确认能打开书架和正文。

Service Worker 预缓存应用的 HTML、CSS、JS、Worker、图标与 manifest；小说正文单独保存在 IndexedDB。新版本会显示“更新应用”，用户点击后激活更新并刷新，避免阅读途中突然换版本。开发模式不启用 Service Worker，离线需生产构建验证。

浏览器可能因用户清理、隐私模式、空间压力等删除网站数据。页面提供持久存储申请，但浏览器可拒绝，也不保证永久保留。**定期导出备份才是长期保存的保障。** 没有自动跨设备同步；换域名或部署路径也可能改变可访问的数据库/缓存范围。不要把同一域名下的其他不受信任应用与私人书房混用，因为 IndexedDB 以 origin 隔离，不按 URL 路径隔离。

## 私人阅读链接（手机点开即读）

可选功能：本机运行 `node scripts/create-private-book.mjs 本地小说.txt`，生成 `public/shared/随机编号.jdb` 加密文件。仅把该加密文件随工程发布；完整私人链接和随机密钥保存在被 Git 忽略的 `.tools/private-books/`，绝不能提交到仓库。

私人链接使用 `#private/编号/密钥`，密钥放在 URL fragment 中。手机首次打开完整链接后，在 Worker 中以 Web Crypto AES-256-GCM 解密、解析并自动保存书架，再直接打开阅读。以后同一设备重开完整链接会使用本地书籍和进度，不重复下载，也可离线使用。主屏幕独立存储中若还没有这本书，需要在线再次打开完整链接。

**任何拿到完整链接的人都能解密这本书，请勿公开转发。** 这不是登录系统，也不自动同步跨设备进度。GitHub Pages 的公共资源中只有密文，托管该应用的人仍控制应用代码，因此该方式不防范网站代码被恶意更改；请仅使用自己信任的部署。备份包含解密后的正文，仍需自行妥善保管。

## GitHub Pages 部署

1. 新建 GitHub 仓库，将工程提交至 `main`。`.gitignore` 已忽略 TXT、EPUB、备份、依赖与构建产物。提交前确认私人的小说和备份未被暂存；不需要上传目录中的小说。
2. 仓库 Settings → Pages → Source 选择 **GitHub Actions**。
3. 推送 `main`，或在 Actions 手动运行“Deploy Jingdu to GitHub Pages”。工作流安装依赖、运行单元测试、构建并发布 `dist`。
4. 在 Pages / Actions 查看部署返回的真实网址（一般为 `https://用户名.github.io/仓库名/`）。

Vite 使用相对 `base: './'`，manifest 的 start_url/scope 也为相对路径。阅读路由放在 URL hash，刷新不会访问不存在的服务器路径。支持仓库子路径与自定义域名；访问目录时保留末尾 `/`。远程发布状态以 GitHub Actions 的实际结果为准。原始 TXT 和本地书架不会以明文随应用部署上传到 GitHub；可选私人阅读链接仅发布加密书籍文件。

## 实现结构

```text
src/components/       书架配套 UI、导入、阅读器、设置、对话框
src/lib/parser.ts     编码检测、章节识别、连续全文备用切分
src/lib/db.ts         IndexedDB、事务、备份完整性校验
src/workers/          后台解码与解析
src/types.ts          书籍、位置、章节与备份数据结构
tests/                编码、章节、大文件、存储与备份测试
e2e/                  真实浏览器导入、恢复、备份、离线与布局测试
```

正文后台按 512 KiB 分块解码；UTF-8 严格检测失败后尝试 GB18030，支持 BOM 的 UTF-8/UTF-16，也可手动选编码。字符集启发式不能保证自动识别所有混合/损坏文本，导入前请检查预览。

章节只匹配独立短行，支持中文数字、阿拉伯数字与 Chapter 格式，句末标点排除部分正文误识别，相邻重复标题合并为一个目录条目。无法识别时按连续全文分节。每节上限 18,000 UTF-16 代码单元、320 个换行，尽可能沿换行切分且避开代理对；所有章节拼接可恢复解码后的全文，不改写文字。目录每批只显示 80 项。只从数据库取当前节，正文节点按节缓存，滚动进度界面每约 600ms 更新，避免整本挂入 DOM 或每次滚动重新构造正文。

位置锚点由“阅读节索引 + 原文段落字符偏移 + 段内相对高度”组成，样式改变、重新打开与横竖屏切换时恢复。用像素偏移以外的锚点提高字体变化后的稳定性；手动改变窗口大小/系统字体后，段内恢复仍可能有少量视觉偏差。

## 首版边界

- 已支持多本 TXT、章节目录与搜索、主题与字号等排版设置、独立进度、书签、搜索/排序/删除、完整备份恢复、离线 PWA 和 Pages 配置。
- 暂不支持 EPUB、统计、自定义封面、导入后元数据编辑、自动跨设备同步。IndexedDB schema 和模块边界可继续扩展这些能力。
- TXT 上限 80 MB；JSON 备份导入上限 200 MB。分块解码最终仍在 Worker 汇总解码文本和章节，书籍导入采用单次原子事务；不是恒定内存的流式存储。多本超大书的 JSON 备份会产生内存峰值，建议桌面操作。四百万字级是当前验证目标。
- 页面被系统强制杀死时，最后一次写入之后的少量滚动可能丢失；无法保证强杀瞬间的异步写入完成。
- 一份书架适合单窗口使用；多个标签页同时阅读同一本书时最后写入的位置生效。
- 首选 iOS/iPadOS Safari 17+ 与近期桌面 Chrome；真实 iPhone 的安装、存储权限、内存压力和系统回收需在设备上验收。
